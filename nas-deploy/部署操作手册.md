## 2. 把文件夹搬到 NAS（图形界面，推荐）

你的 SMB 共享拒绝覆盖写入，所以**不要覆盖旧目录**；用一个全新目录名上传。

1. 飞牛 NAS 网页登录 → 打开「文件管理」。
2. 进入你的 Docker 共享目录（通常是 `docker`，即你之前映射的 `\\192.168.1.99\docker`）。
3. 新建文件夹，命名 `metals-close`（若已存在同名，改名 `metals-close-2`）。
4. 进入该文件夹 → 点「上传」→ 选择本地 `nas-deploy` 目录里的**全部内容**（含以点开头的 `.env`，上传后要能看到它）。
   - 隐藏文件提示：若上传后目录里看不到 `.env`，用文件管理器的「显示隐藏文件」开关确认它确实进去了。
5. 上传完成后，确认目录里能看到 `docker-compose.yml`、`Dockerfile`、`.env`、`backend`、`web`、`data`、`tools` 这几项。

> 备选：你也可以直接从 Windows 资源管理器把 `nas-deploy` 里的文件拖到 `\\192.168.1.99\docker\metals-close`；因为是新目录，不会触发覆盖失败。后续更新文件时若报「拒绝访问」，先在 NAS 文件管理器里删掉旧的同名文件再上传。

## 3. 飞牛 Docker 一键建项目（图形界面）

1. 打开飞牛 NAS → 应用中心/桌面 → 「Docker」。
2. 左侧选「Compose」→ 右上角「新建项目」。
3. 表单填写：
   - **项目名称**：`metals-close`（随意，英文不要空格）
   - **路径**：点「选择」，选第 2 步上传的 `docker/metals-close` 目录
   - **来源**：选「使用现有的 docker-compose.yml」（目录里已有该文件）
   - 勾选「**创建项目后立即启动**」
4. 点「确定 / 完成」。会出现构建窗口：拉取 `python:3.13-slim` → 安装依赖 → 创建容器 → 启动。
   - 国内拉基础镜像慢是正常的，等 2–5 分钟；若卡在拉镜像，先在飞牛 Docker 设置里配一个国内镜像加速再重试。
   - 看到日志出现 `Container ... Started` / `Exited: 0` 即为成功，可关闭窗口。
5. 左侧切到「容器」，确认 `metals-close` 状态是**运行中**（健康状态 Healthy）。

## 5. 日常使用与更新

- **每天导入新数据（推荐：脚本自动采集真实值）**：本项目已附 `tools/build_daily_snapshot.py`，从 Yahoo Finance 免费公开源采集并计算，**不会编造数字**。在有 Python 的机器上执行：
  ```
  python tools/build_daily_snapshot.py --date 2026-11-16
  ```
  产出 `data/seed/2026-11-16.json` + 4 个配套数据集（均带日期前缀，不会覆盖旧报告）。把这些文件放进 NAS 的 `docker/metals-close/data/seed/`，然后 Docker → Compose → `metals-close` → 重启容器，`entrypoint.sh` 自动增量入库。
  - 口径：GC=F / SI=F 为 COMEX 连续期货日收盘，与 P0 样例（TVC 现货口径）不可混用；快照 `mode=REAL`。
  - 免费源拿不到的字段（本地溢价 / COMEX 仓单 / 交割通知）显示「—」，不填假数。
  - 当前库中已有两条：2026-11-13（样例 MOCK）与 2026-11-16（真实 REAL），页面默认展示最新收盘日，顶部日期框可切换。
- **手工导入**：也可直接把已有的 `YYYY-MM-DD.json`（及配套 4 个 JSON）放进 seed 目录后重启容器。
- **改配置**（邮箱/Resend/端口）：编辑 `.env` 或 `docker-compose.yml` 后必须**重建容器**才生效。飞牛图形界面：Compose → 停止项目 → 修改文件 → 重新启动项目。
- **改文件报「拒绝访问」**：SMB 不能覆盖；先在 NAS 文件管理器删除旧文件，再上传新文件。
- **数据备份**：整个 `docker/metals-close/data` 目录就是你的数据库和种子数据，复制走即完成备份。
- **增减订阅邮箱**：生产环境不想开命令行时，可临时进容器终端执行：
  - 增加：`python tools/seed_subscriber.py add 新邮箱@example.com --days 365`
  - 停用：`python tools/seed_subscriber.py remove 邮箱@example.com`

## 6. 内网快速验证模式（不发邮件，仅限局域网）

如果你暂时没有 Resend，只想先看版式：
1. 编辑 `.env`，把 `MC_DEV_MODE=1`、`MC_COOKIE_SECURE=0`；
2. 按第 3 节重建项目；
3. 登录时验证码会直接显示在弹窗的虚线框里（不会发邮件），填进去即可登录。
4. **正式对外前必须改回 `MC_DEV_MODE=0` 并配好 Resend**，否则任何人都能收到验证码、等于无鉴权。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 构建卡在拉 `python:3.13-slim`（几十分钟停在十几 MB） | 国内直连 Docker Hub 龟速 | **本包 Dockerfile 已改走 `docker.1ms.run/library/python:3.13-slim`**（2026-11-17 实测完整鉴权 + 拉 manifest 返回 200）。删旧 Dockerfile 再传新版，重建项目即可 |
| 报 `401 Unauthorized` on `load metadata for ...` | 镜像前缀用了 `docker.fnnas.com` | 飞牛内置源**只能配在 Docker 设置→镜像加速**，不能写进 `FROM` 前缀（401 无鉴权挑战头，buildx 失败）。改用 `docker.1ms.run` 或 `docker.m.daocloud.io` 前缀 |
| 容器反复重启 | `.env` 没被读取 / 密钥为空 | 确认 `.env` 在项目根目录、自检脚本全 OK |
| 页面能开但登录转圈 | Resend 没配或域名未验证 | 看日志 `send code failed`；或临时用第 6 节模式验证 |
| 登录后 Cookie 失效、反复退回登录 | `MC_COOKIE_SECURE=1` 但用 HTTP 访问 | 内网访问时改回 `0` 并重建 |
| 浏览器打不开 `8790` | 端口被占 / 防火墙 | 换 8791；确认飞牛防火墙放行该端口 |
| 数据还是旧的 11-13 | 种子只有这一天 | 这是样例数据；按第 5 节导入当日 JSON |
| 手机访问排版错乱 | 缓存 | 强制刷新；本版已做 360/390/768 三档适配 |
